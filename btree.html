B-Tree Data Structure

Python Algorithms Data Structures Disk-Based Storage Disk I/O Optimization Database Indexing

Project Overview

This project implements a disk-based B-Tree data structure that simulates how databases manage indexing when nodes must be persisted to disk instead of memory. The tree supports efficient insert(key, value) and find(key) operations while maintaining balanced height, sorted keys, and configurable branching factors (M and L). Each node is stored in its own disk block through a custom DISK interface, introducing strict constraints that resemble real storage systems.

Task Requirements

Core Operations
• insert(key, value): insert or overwrite keys while maintaining B-Tree invariants
• find(key): return the value for a key or None

Structural Constraints
• Nodes remain sorted
• Height stays balanced
• Branching factors defined by M (internal nodes) and L (leaf nodes)

Disk-Based Architecture
• Each node resides in a separate disk block
• Only m, l, and the root address remain in memory
• All interactions occur through:
    – DISK.new()
    – DISK.write(address, node)
    – DISK.read(address)

Implementation & Problem-Solving Highlights
• Managing a fully disk-backed data structure introduces complexity: every update requires explicit writes, and stale in-memory references easily lead to structural corruption.
• Node splitting is non-trivial: handling medians, redistributing children, and maintaining invariants across recursive levels requires precise logic.
• Debugging is more difficult than with in-memory trees due to incorrect disk writes, missing updates, or reading outdated nodes — issues that pointer-based trees do not face.
• Testing reveals subtle structural bugs (incorrect child pointer movement, unbalanced splits, off-by-one errors), resolved through Pytest and custom visualizations.
• The project requires careful coordination between algorithm design and disk constraints, making it significantly more challenging than standard B-Tree implementations.
