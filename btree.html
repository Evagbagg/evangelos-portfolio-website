Project Overview

This project implements a disk-based B-Tree data structure that simulates how databases manage indexing when nodes must be persisted to disk instead of memory. The tree supports efficient insert(key, value) and find(key) operations while maintaining balanced height, sorted keys, and configurable branching factors (M and L). Each node is stored in its own disk block through a custom DISK interface, introducing strict constraints that resemble real storage systems.

⚙️
Core Operations
  • insert(key, value) — Insert or overwrite keys while maintaining B-Tree invariants
  • find(key) — Return the value for a key or None
🌲
Structural Constraints
  • Keys remain sorted
  • Height stays balanced
  • Branching factors defined by M (internal nodes) and L (leaf nodes)
💾
Disk-Based Architecture
  • Each node stored in a disk block
  • Only m, l, and the root address remain in memory
  • All interactions occur through DISK.new(), DISK.write(), DISK.read()
🧠
Implementation & Problem-Solving Highlights
  • Managing a fully disk-backed data structure introduces complexity: every update requires explicit writes, and stale references easily corrupt the tree.
  • Node splitting is non-trivial: handling medians, redistributing children, and maintaining invariants across recursive levels requires precise logic.
  • Debugging is harder than in-memory trees because errors arise from incorrect disk writes or reading outdated nodes.
  • Testing uncovered subtle structural bugs—off-by-one errors, incorrect pointer movement, unbalanced splits—resolved through Pytest and visualization.
  • Overall, the project requires tight coordination between algorithm design and simulated storage constraints, making it far harder than standard B-Tree implementations.
